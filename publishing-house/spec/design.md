# Red Hat Satellite Basics 6.19

## Overview

This lab introduces participants to Red Hat Satellite 6.19 as a lifecycle management platform for Red Hat Enterprise Linux hosts. It is a migration of an existing Zero Touch guided lab that covers the core Satellite workflow from initial configuration through content filtering, errata application, and AI-assisted management. Participants will configure lifecycle environments, content views, and activation keys; register RHEL 10 hosts via the hammer CLI; apply errata and install software; explore Red Hat Lightspeed Advisor and Vulnerability services; and use an AI assistant integrated with Satellite via the Model Context Protocol to query inventory and trigger remote execution jobs using natural language.

## Target Audience

- **Role:** Linux system administrators, platform engineers, and IT operations staff responsible for managing RHEL infrastructure
- **Experience level:** Beginner
- **What they already know:** Basic Linux command-line familiarity — SSH, terminal navigation, and dnf package manager; no prior Red Hat Satellite experience required
- **What they don't know:** How to configure and use Red Hat Satellite 6.19 to manage software delivery, host registration, errata remediation, content filtering, and AI-assisted operations on RHEL 10 hosts

## Prerequisites

- Basic Linux command-line familiarity (SSH, terminal navigation, dnf package manager)
- No prior Red Hat Satellite experience required
- Cannot be validated automatically — these are informal skill prerequisites, not lab-enforced checkpoints

## Learning Objectives

1. Configure lifecycle environments, content views, and activation keys in Red Hat Satellite 6.19 to control software delivery to RHEL 10 hosts
2. Create host groups and assign Ansible roles to enforce baseline system configuration across managed hosts
3. Register RHEL 10 hosts to Satellite using a global registration script generated by the hammer CLI
4. Manage Red Hat Lightspeed Advisor recommendations and apply auto-generated Ansible playbooks for remediation in a disconnected Satellite environment
5. Configure the Satellite Client 6 repository and install katello-host-tools-tracer to detect services requiring restart after package updates
6. Apply errata to managed hosts and resolve service traces using Satellite remote execution
7. Install and filter software packages on managed host collections using Satellite content management and package filtering capabilities
8. Explore Satellite MCP server integration to query inventory and trigger remote execution jobs using natural language prompts

## Environment

**Learner view:** When the lab starts, Red Hat Satellite 6.19 is fully installed on the `satellite.lab` host and accessible via the Satellite Web UI with pre-configured admin credentials. RHEL 10 BaseOS and AppStream repositories are already synchronized from the Red Hat CDN. Two RHEL 10 managed hosts (`rhel1.lab` and `rhel2.lab`) are provisioned and accessible via SSH from `satellite.lab`. A fourth host (`rhel-ai.lab`) runs opencode with the minimax-m2 LLM for the Satellite AI Integration module. The Satellite Client 6 repository is pre-synced and available for the Tracer module.

**Automation needed:** Yes

Pre-provisioned by setup automation:
- Red Hat Satellite 6.19 server installed and configured on `satellite.lab`
- RHEL 10 BaseOS and AppStream repositories synchronized from the Red Hat CDN
- Satellite Client 6 repository pre-synced (available but not yet added to content views)
- RHEL 10 managed VMs (`rhel1.lab`, `rhel2.lab`) with SSH access from `satellite.lab`
- RHEL AI host (`rhel-ai.lab`) with opencode and minimax-m2 model pre-configured and the Satellite MCP server enabled
